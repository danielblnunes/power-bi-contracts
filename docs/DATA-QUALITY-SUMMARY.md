## Critical data-quality issues to fix in Power Query (Phase 1)

### 1. Deliverables Rights[Status] — typo
Value `600 Delivered` appears alongside `Delivered`, `In Progress`, `Not Started`. Replace `600 Delivered` → `Delivered` in Power Query before load.

### 2. Deliverables Rights[Due_Date] — mixed types
Column contains both real dates AND text values (`N/A`, `90 days after order`). Change type to **Date** in Power Query — non-date values become `null` (the intended behavior for non-dateable items).

### 3. Deliverables Rights[Value_AED] — 87 of 91 rows are NULL
This is expected: most rights/obligations (IP rights, naming rights, obligations) are non-monetary. **Do NOT coalesce to 0** — blanks are correctly excluded by DAX SUM. The 4 valued rows are: `3,000,000`, `880,000`, `5,500`, and one more — all VIK items.

### 4. Agreements row AGR-2022-003 — mostly empty
Only `Agreement_ID`, `Agreement_Type` (Media Rights), `Counterparty_Type` (Supplier), `Contract_Category` are populated. All other columns are null. This row will appear as a contract with no value, dates, or counterparty name. Either:
- Exclude it in Power Query with a filter on `Agreement_ID <> "AGR-2022-003"`, OR
- Keep it (the dashboard will naturally show "1 Media Rights contract with no value") to highlight incomplete data.

### 5. Agreement_Status nulls
3 payment rows out of 10 have a null `Status`. These show up as a blank in "Payments by Status" and won't be counted in `Paid Amount` or `Outstanding Amount`. Flag for the data owner. No Power Query change needed — DAX `IN {...}` filters ignore nulls cleanly.

## Counterparty data note

`Agreements[Counterparty_Name]` contains both real counterparties (Etihad Rail, ERREA) AND placeholder samples ("Sample Sponsor", "Sample Cleaning Services"). Once real data arrives, those samples disappear. The dashboard design tolerates this — counts and values roll up regardless.

## Keep-as-is guidance for DAX

The following should NOT be zero-coerced in DAX (let blanks stay blanks):

- `Total_Contract_Value_AED`, `Annual_Value_AED` — NULL agreement rows should NOT contribute 0.
- `'Payment Schedule'[Amount_AED]` — already 100% populated.
- `'Deliverables Rights'[Value_AED]` — 87/91 NULL by design.

The measures in `measures/measures_catalog.py` use `SUM` / `AVERAGE` / `COUNTROWS` which all handle blanks correctly without `+ 0` suppression. The DAX linter confirms no `+ 0` blank-suppression patterns in any measure.
